# 1.3.0 代码逻辑修复与优化

日期：2026-10-13。对应同日代码检查报告中的 R01–R06 与三项优化建议。版本保持 1.3.0，网络协议 45，配置 Schema 2。

## 功能修复

| 编号 | 问题 | 修复结果 |
| --- | --- | --- |
| R01 | 拖动中删除、应用或切换操作导致崩溃、元素恢复或保存旧坐标 | 统一结束拖动，保存当前可见位置，再执行删除、复制、属性、撤销、键盘微调、关闭等操作；拖动按元素 ID 与起始选择集校验；右键释放不会结束左键拖动。 |
| R02 | 数据包已替换后，资源包准备或备份失败却没有恢复数据包 | 每次备份成功后立即登记文件事务，任一步失败均逆序恢复已替换目标并恢复设置；恢复失败保留恢复材料，以附加异常记录原因。重载失败后的回滚也保留未恢复的材料。 |
| R03 | 条件变化时固定属性加成没有启用或移除 | 带条件的固定属性纳入周期性差异更新，无条件固定属性保持原路径；完整重载先移除两类旧修饰符，避免相同 UUID 在静态与条件属性之间切换时互相覆盖。 |
| R04 | 同 ID 天赋与物品共用触发器、冷却及次数 | 触发来源包含定义类型，天赋持有与物品装备分别判断；物品的冷却、激活次数和移动距离进度使用独立状态键。 |
| R05 | 保存后引用、删除与复制仍使用旧元数据 | 打开相关操作时读取最新 bootstrap；服务器先发送元数据再发送保存确认。保留草稿自身版本，继续检测并发冲突。 |
| R06 | 新计数器改 ID 保存后引用仍指向默认 ID | 保存成功后更新已提交 ID，引用和后续操作使用正确对象。 |

## 优化

1. 编辑页缓存完整草稿指纹，只在字段值或编辑操作变化时重新序列化；保存与离开检查仍读取即时草稿。无条件动作跳过条件上下文构建，同次属性刷新复用只读上下文。
2. 自动合成按运行快照缓存已排序的候选列表；同轮候选共用条件上下文，成功后重建，保留连锁合成需要的中间属性和物品状态；每批结束仅进行一次最终物品栏及玩家状态同步，移除调用方重复刷新。单次检查对无效目标、不可合成或已拥有目标保留快速返回。
3. 六类定义共用版本检查、JSON 校验、完整编译、持久化、激活和回执流程；保留各类文件格式、网络包编码及提交后的特定刷新行为。

没有进行长期性能采样，不宣称具体帧率或耗时提升。

## 旧触发器状态兼容

天赋沿用原状态键。物品改用带 `item|` 前缀的状态键。当前定义中没有同 ID 天赋时，旧物品冷却、次数与距离进度在首次触发判断前迁移；已有新键优先保留。

若旧存档中天赋和物品曾共用同一个状态键，无法可靠拆分历史贡献：旧键保留给天赋，物品从自己的独立状态开始。该行为只涉及跨类型同 ID 配置；当前涟漪包未使用这种组合。触发器状态仍使用原有字符串映射结构，无需调整 NBT 或网络字段。
